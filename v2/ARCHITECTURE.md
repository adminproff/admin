# OP Kiosk OS 2.0 — архитектура чистой переработки

## 1. Статус прежних версий

Линейка 1.3.x отозвана. Она не должна использоваться для новой установки на внутренний накопитель.

Причина: live-режим и отдельные компоненты проверялись, но полный обязательный цикл `USB -> установка -> удаление USB -> холодная загрузка внутреннего диска -> Chromium -> сервисное меню` не был надёжно пройден до выдачи пользователю.

## 2. Базовый принцип версии 2.0

OP Kiosk OS 2.0 использует штатный Debian Live Installer, включаемый через `live-build --debian-installer live`.

Собственный код больше не выполняет ручное переразбиение диска, копирование работающего overlay-root, установку GRUB и сборку initramfs. Эти операции выполняет Debian Installer.

Собственный код отвечает только за:

- состав установленной системы;
- kiosk-сессию;
- Chromium;
- сетевые настройки;
- сервисное меню;
- диагностику;
- проверки перед публикацией.

## 3. Режимы одного ISO

### 3.1 Запустить без установки

- загружается Debian Live;
- автоматически стартует графическая kiosk-сессия;
- Ethernet получает адрес по DHCP;
- Wi-Fi настраивается из сервисного меню;
- изменения live-режима не считаются постоянными.

### 3.2 Установить OP Kiosk OS

- запускается отдельный Debian Installer;
- Chromium, Openbox и пользовательская kiosk-сессия в процессе установки не запускаются;
- разметка диска, файловые системы, копирование live-системы, fstab, initramfs и GRUB выполняются Debian Installer;
- перед окончанием установки выполняется поздняя проверка конфигурации OP Kiosk OS.

## 4. Установленная система

### 4.1 Загрузка

```text
UEFI/BIOS
  -> GRUB
  -> Debian 13
  -> systemd graphical.target
  -> LightDM autologin: kiosk
  -> Openbox
  -> Chromium --kiosk
```

### 4.2 Графическая сессия

Используется стандартный LightDM с автоматическим входом пользователя `kiosk` и отдельной XSession `op-kiosk`.

Не используются:

- getty-autologin;
- `.bash_profile -> startx`;
- собственный запуск Xorg из root-службы;
- маскирование системных виртуальных терминалов ради запуска браузера.

### 4.3 Браузер

Chromium запускается непривилегированным пользователем `kiosk`.

Обязательные свойства:

- полноэкранный kiosk-режим;
- автоматический перезапуск после сбоя;
- отдельные каталоги профиля, кеша и Crashpad;
- запрет DevTools политикой Chromium;
- рабочий URL хранится в `/var/lib/op-kiosk/kiosk.conf`;
- локальная диагностическая страница используется при пустом URL;
- журнал: `/var/log/op-kiosk/browser.log`.

## 5. Сеть

Используется NetworkManager.

Обязательные функции:

- Ethernet;
- Wi-Fi;
- WPA2-PSK;
- WPA3-SAE;
- DHCP;
- статический IPv4;
- пользовательские DNS-серверы;
- proxy для Chromium;
- автоподключение;
- приоритет Ethernet над Wi-Fi.

Метрики маршрутов:

- Ethernet: `100`;
- Wi-Fi: `600`.

Сетевые профили сохраняются в `/etc/NetworkManager/system-connections/`.

## 6. Сервисное управление

Основные сочетания:

```text
Ctrl+Alt+M — сервисное меню
Ctrl+Alt+T — диагностический xterm
```

Резервные сочетания не должны использовать `Ctrl+Alt+F1..F12`.

Пароль администратора хранится не в открытом виде. Пользователь `kiosk` не получает полный sudo. Разрешаются только специально перечисленные root-команды.

Сервисное меню должно содержать:

1. Состояние сети.
2. Подключение к Wi-Fi.
3. Удаление Wi-Fi-профиля.
4. DHCP / статический IPv4.
5. Рабочий URL.
6. Proxy.
7. Перезапуск браузера.
8. Перезагрузка.
9. Выключение.
10. Диагностический отчёт на USB.

Пункт ручной установки из уже запущенного браузера отсутствует. Установка запускается только отдельным пунктом загрузочного меню ISO.

## 7. Безопасность выбора диска

Выбор и очистка диска выполняются Debian Installer.

Дополнительно:

- загрузочный USB не должен автоматически выбираться целью;
- перед подтверждением показываются модель, размер и устройство;
- полностью автоматическая разметка допускается только в CI;
- пользовательская сборка требует явного подтверждения диска.

## 8. Диагностика

Журналы:

```text
/var/log/op-kiosk/session.log
/var/log/op-kiosk/browser.log
/var/log/op-kiosk/network.log
/var/log/op-kiosk/health.log
```

Команда формирования архива:

```text
/usr/local/sbin/op-kiosk-support-bundle
```

Архив не должен включать Wi-Fi-пароли, хеш административного пароля и Chromium cookies.

## 9. Обязательные автоматические тесты

Сборка не публикуется, пока не пройдены все пункты.

### 9.1 Live

- BIOS-загрузка ISO;
- UEFI-загрузка ISO;
- DHCP;
- Xorg/LightDM/Openbox;
- Chromium действительно отрисовал локальную страницу;
- `Ctrl+Alt+M` открыл меню;
- `Ctrl+Alt+T` открыл xterm.

### 9.2 Установка BIOS

- пустой виртуальный диск 8 ГБ;
- запуск пункта Install;
- окончание Debian Installer без ошибки;
- выключение виртуальной машины;
- удаление ISO;
- холодная загрузка внутреннего диска;
- DHCP;
- Chromium;
- сервисное меню.

### 9.3 Установка UEFI

Тот же полный цикл с OVMF.

### 9.4 Повторные загрузки

- три последовательные холодные загрузки установленной системы;
- отсутствие ручного вмешательства;
- отсутствие остановки на текстовой консоли;
- Chromium запускается каждый раз.

### 9.5 Отрицательные тесты

- установщик не выбирает ISO/USB как целевой диск;
- диск менее минимального размера отклоняется;
- отсутствие сети не мешает загрузке локальной страницы;
- падение Chromium вызывает его восстановление;
- неверный пароль не открывает сервисное меню.

## 10. Правило выпуска

До прохождения полного end-to-end теста запрещено использовать формулировки:

- «готовый образ»;
- «финальный релиз»;
- «можно устанавливать».

Допустимый статус до этого момента:

```text
экспериментальная сборка для автоматического тестирования
```

Физический тест на HP t530 остаётся последним аппаратным приёмочным этапом после автоматического PASS BIOS+UEFI установки в QEMU.
